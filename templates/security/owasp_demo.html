A01
Broken Access Control CRITICAL
Users accessing resources they shouldn't
Attack — IDOR (Insecure Direct Object Reference)

As Patient A, try to access Patient B's medical record by changing the ID in the URL:

GET /records/1/ ← another patient's record GET /appointments/3/ ← another user's appointment
Defense Applied

Every view checks ownership before returning data:

# records/views.py is_allowed = ( record.patient == request.user or record.doctor == request.user or profile.is_admin() ) if not is_allowed: SecurityLog.log(request, 'ACCESS_DENIED', ..., is_threat=True) return redirect('record_list') # 🚫 BLOCKED + LOGGED

Try it: Log in as a patient and visit /records/1/ — you will be redirected and the attempt appears in Security Logs.

A02
Cryptographic Failures CRITICAL
Sensitive data stored or transmitted insecurely
Attack — Plain Text Password Storage

If passwords were stored as plain text, a database breach exposes everything. Open db.sqlite3 and check the auth_user table.

Defense — PBKDF2 + SHA256 Hashing
# What you see in the database (NOT plain text): pbkdf2_sha256$720000$randomsalt$hashedvalue== # Django handles this automatically — never stores plain text # settings.py — session cookie protection: SESSION_COOKIE_HTTPONLY = True # JS cannot read cookie SESSION_COOKIE_SAMESITE = 'Lax' # CSRF protection SESSION_COOKIE_AGE = 3600 # Auto-expire in 1 hour
A03
Injection (SQLi + XSS) CRITICAL
Malicious input executed as code
SQLi Attack — Try these in any search/input field
BLOCKED! Django ORM uses parameterized queries. Your input was treated as data, not SQL. Attack logged to Security Logs.
XSS Attack — Try in appointment reason or profile fields
BLOCKED! bleach.clean() stripped all HTML tags. Stored as plain text:
Defense Code
# SQLi — Django ORM (parameterized queries, NEVER string concat) records = MedicalRecord.objects.filter(title__icontains=user_input) # XSS — bleach sanitization on every text input import bleach clean = bleach.clean(user_input, tags=[], strip=True) # XSS — Django templates auto-escape by default {{ user_input }} ← safe, {{ user_input|safe }} ← NEVER use this
A04
Insecure Design HIGH
No rate limiting, brute force possible
Attack — Brute Force Login

Without protection, an attacker can try millions of passwords. Go to /accounts/login/ and enter wrong credentials 5 times.

Defense — Session-Based Lockout
# accounts/views.py MAX_ATTEMPTS = 5 LOCKOUT_SECONDS = 300 # 5 minutes if attempts >= MAX_ATTEMPTS: request.session['lockout_until'] = time.time() + LOCKOUT_SECONDS SecurityLog.log(request, 'ACCOUNT_LOCKED', ...) # User sees: "Too many failed attempts. Locked for 5 minutes."
A05
Security Misconfiguration HIGH
DEBUG mode, default credentials, exposed errors
Attack — Information Leakage via DEBUG Mode

With DEBUG=True in production, error pages expose stack traces, database structure, installed apps, and secret keys to attackers.

Defense — .env File + Secure Headers
# .env file (never committed to Git — in .gitignore) SECRET_KEY=random-unpredictable-string DEBUG=False ← False in production # settings.py — security headers SECURE_BROWSER_XSS_FILTER = True SECURE_CONTENT_TYPE_NOSNIFF = True X_FRAME_OPTIONS = 'DENY' ← blocks clickjacking SESSION_COOKIE_HTTPONLY = True ← JS cannot steal session

A07
Identification & Authentication Failures CRITICAL
Weak passwords, session not invalidated on logout
Attack — Weak Password + Session Fixation

Try registering with password "12345678" — it gets rejected. Session fixation: attacker sets session ID before login, then hijacks it.

Defense
# Strong password policy in settings.py AUTH_PASSWORD_VALIDATORS = [ {'NAME': '...MinimumLengthValidator', 'OPTIONS': {'min_length': 8}}, {'NAME': '...CommonPasswordValidator'}, ← blocks "password123" {'NAME': '...NumericPasswordValidator'}, ← blocks "12345678" ] # Session fixation prevention on login request.session.cycle_key() ← new session ID after login # POST-only logout prevents CSRF logout attacks if request.method == 'POST': logout(request)
A08
Software & Data Integrity Failures HIGH
Malicious file uploads, extension spoofing
Attack — Extension Spoofing

Rename malware.exe to malware.jpg and try uploading it in the medical records attachment field.

Defense — Real MIME Type Check
# records/forms.py — python-magic reads file BYTES import magic mime = magic.from_buffer(file.read(1024), mime=True) file.seek(0) ALLOWED = ['image/jpeg','image/png','image/gif','application/pdf'] if mime not in ALLOWED: raise ValidationError(f"File type '{mime}' not allowed.") # Rename .exe → .jpg FAILS because magic reads actual bytes # not just the filename extension!
A09
Security Logging & Monitoring Failures MEDIUM
Attacks not detected because nothing is logged
Without Logging

Without logging, an attacker can probe your system for hours — trying SQLi, brute forcing passwords — and you'd never know until the damage is done.

Defense — SecurityLoggingMiddleware
# security/middleware.py — scans EVERY request automatically class SecurityLoggingMiddleware: def _scan_request(self, request): for value in GET_and_POST_values: if sqli_pattern.search(value): SecurityLog.log(request, 'SQLI_ATTEMPT', ..., is_threat=True) if xss_pattern.search(value): SecurityLog.log(request, 'XSS_ATTEMPT', ..., is_threat=True) # Every login, logout, access denial, file rejection → logged # View all logs at: /security/logs/

A10
Server-Side Request Forgery (SSRF) MEDIUM
App fetches attacker-controlled URLs
Attack — Internal Network Access

If the app fetches URLs from user input, an attacker could supply http://localhost/admin or http://169.254.169.254/ (AWS metadata) to access internal systems.

Defense — No User-Supplied URLs + Validation
# MediSecure never fetches user-supplied URLs. # If URL input is needed, validate strictly: import ipaddress from urllib.parse import urlparse def is_safe_url(url): parsed = urlparse(url) host = parsed.hostname # Block private/internal IP ranges try: ip = ipaddress.ip_address(host) if ip.is_private or ip.is_loopback: SecurityLog.log(request, 'SSRF_ATTEMPT', ..., is_threat=True) raise ValueError("Internal URLs not allowed") except ValueError: pass # it's a domain name, proceed
